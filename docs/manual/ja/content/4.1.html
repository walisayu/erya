4.1.1

既定が「ターミナル安全」な理由

押した組み合わせをターミナルが必ず届けてくれるとは限らないからです。

内蔵の既定プロファイルは Erya Terminal Safe といいます。多くの環境で失敗する 3 種類の組み合わせを意図的に避けています：

避けているもの理由
Ctrl＋ファンクションキーmacOS がシステム用に予約しており（Spaces、Mission Control）、プログラムまで届きません。
Alt／Option に依存する組み合わせmacOS では Option が特殊文字の入力に使われ、多くのターミナルは設定しないと Meta として送りません。
修飾付き矢印（Alt+Shift+← など）そもそも報告しないターミナルが相当数あります。

その代償として16 の応用操作が未割り当てです：定型文とマクロの 8 つ（2.4.8 参照）、矩形の移動 4 つと塗りつぶし 1 つ（2.2.6 参照）、段落の再整形 2 つ（3.1.8 参照）、そしてステータス行で足りている「カーソル位置の表示」。機能自体はすべてあり、キーを与えるだけです。一覧は 4.4.6 にあります。

旧セットは無くなっていません

1.0 の完全な組み合わせは Erya Classic として残っており、F2 を押して選ぶだけで戻せます。修飾付き矢印や Alt 組み合わせを報告するターミナル（GNOME Terminal や Windows Terminal など）なら、Classic のほうが快適です。

4.1.3

システム設定で切り替える

いちばん簡単な方法で、ファイルを触りません。

爾雅 Erya │ システム設定
↑/↓ 項目 ←/→ 選択 E キー編集 Enter 適用 Esc キャンセル
▶ キーバインド: ◀ Erya Terminal Safe ▶ 表示言語: ◀ 日本語 (ja) ▶
Erya Terminal Safe │ 日本語
矢印キーで選択し、Enter ですべてのタブに適用します
  1. F2 を押します。
  2. ↑ ↓ でキーバインドの行へ（選択中の行は反転し ▶ が付きます）。
  3. ← → でプロファイルを変えます。一覧は keymap/ から読み込まれます。
  4. Enter で適用。「設定を適用しました：Erya Classic／日本語」と出て、すべてのタブに即座に反映されます。
  5. Esc で取り消し、何も変わりません。
一覧が空のときは

keymap/ ディレクトリが見つかっていません。ERYA_KEYMAPS_DIR で場所を指定してください（1.2.7 参照）。リリースのアーカイブから実行ファイルだけ取り出したときによく起きます。

Erya の中でキーを変え、自分の TOML として保存します。

  • 保存ではファイル名を尋ね、成功すると「キーマップを保存しました：…」。

自分のプロファイルを常用にするには

2 通りあります。keymap/ に保存して F2 の一覧から選べるようにするか、プラットフォームの既定パスに置いて起動のたびに読ませるかです（4.1.7 参照）。

4.1.5

設定ファイルの書き方

name と [bindings] だけです。

まず全操作が載った雛形を作ります：

erya --print-default-keymap > keymap.toml

記述例
name = "私の設定"

[bindings]
save = "Alt+S"
quit = "Ctrl+X"
search = ["Ctrl+W", "Ctrl+F"]
toggle_rectangular_selection = "Alt+M"
redo = []
  • 1 つの操作に複数のキーを割り当てるには配列で書きます。
  • 空の配列 [] は無効化です。
  • 書かなかった操作は既定のままです。2 つだけ変えたいなら、その 2 行だけ書けば十分です。
  • name はシステム設定と、キーマップエディターの 1 行目に表示されます。
  • 操作名の一覧は 4.4、または --print-default-keymap の出力にあります。
4.1.6

キー名の書き方

修飾キーは + でつなぎ、大文字小文字は問いません。

種類使える名前
修飾キーCtrl、Alt、Shift、Super、Hyper、Meta
通常の文字A〜Z、0〜9、記号
ファンクションキーF1 から F24
移動・編集キーLeft、Right、Up、Down、Home、End、PageUp、PageDown、Insert、Delete、Backspace、Tab、Enter、Esc

例："Ctrl+S"、"Alt+Shift+Right"、"F12"、"ctrl+shift+f"（大文字小文字は不問）。

F1 は割り当てられません

単独の F1 はキー操作ヘルプ用に予約されており、設定ファイルに書くとエラーになります（1.3.8 参照）。意図的な非常口で、プロファイルをどう変えても全一覧を呼べるキーが 1 つ残ります。

4.1.7

設定ファイルの置き場所

指定方法は 3 つ。優先度の高い順です。

  1. --keymap <ファイル>——この実行だけ。最優先です。
  2. 環境変数 ERYA_KEYMAP——--keymap が無いときに使われます。
  3. プラットフォームの既定パス——上の 2 つが無いときに探します：
プラットフォームパス
macOS~/Library/Application Support/Erya/keymap.toml
Linux$XDG_CONFIG_HOME/erya/keymap.toml、未設定なら ~/.config/erya/keymap.toml
Windows%APPDATA%\Erya\keymap.toml
既定パスにファイルが無いのは正常です

Erya は自分で作りません。無ければ内蔵の既定値を使い、警告も出しません。一方、--keymap や ERYA_KEYMAP で明示したパスが読めないときはメッセージが出ます。使うと宣言されたものだからです。

4.1.8

競合とフォールバック

設定が壊れていてもプログラムは止まりません。使われないだけです。

キーバインドを読み込めないため、既定値を使用します：save と search が両方 F9 です
  1. 2 つの操作が同じキー——競合です。どちらを実行すべきか決められません。
  2. キー名の綴り違い、TOML の構文エラー——解析に失敗します。
  3. 単独の F1 を割り当てた——予約キーなので受け付けません。

いずれの場合も Erya は完全な既定プロファイルに戻し（問題の行だけ無視するのではありません）、起動時のメッセージ行に理由を出します。プログラムはそのまま動きます。

いま何を使っているか確かめる

2 行目のヒント行（実際のキーが出ます）、F1 の全一覧、F2 のプロファイル名。3 か所とも本当のことを教えてくれます。

4.1.9

よくあるつまずき

キーを変えるときの 7 つの場面。

症状原因と対処
設定を変えたのに反映されないErya が読む場所に無い（4.1.7）か、却下されて既定に戻っています（4.1.8）。起動時のメッセージを確認してください。
起動時に「キーバインドを読み込めない」競合か構文エラーです。コロンの後に理由が出ます（4.1.8）。
F2 の一覧が空keymap/ が見つかりません。ERYA_KEYMAPS_DIR を設定します（4.1.3）。
Alt の割り当てが効かないターミナルが Option／Alt を Meta として送っていません。別のキーにするか、ターミナル側で有効にします（4.1.1）。
F1 の割り当てが拒否されるF1 は予約キーです（4.1.6）。
名前を付けて保存が失敗する同名のファイルがあります。上書きしない設計なので別名にしてください（4.1.4）。
切り替えたら元に戻すが行削除になったCtrl+Y の意味が 2 つのプロファイルで違います（4.1.2）。
