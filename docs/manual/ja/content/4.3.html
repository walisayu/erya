4.3.1

この章の使い方

機能ではなく「症状」から引いてください。

Erya の反応はほぼすべて最終行に出ます。うまくいかないときにまずすべきことは、その行を最後まで読むことです。たいてい原因が書いてあり、押すべきキーまで書いてあることも少なくありません。

  1. 最終行を読む。黄は報告、白は入力待ち、赤は判断待ちです（1.3.6 参照）。
  2. 2 行目を読む。いま使えるキーが並んでいます。見慣れないキーなら、別の画面にいるか別のプロファイルです。
  3. Esc を押す。どこにいるか分からないとき、必ず 1 階層戻り、何も壊しません。
  4. F1 を押す。機能のキーを探すなら、この一覧が目次です。

4.3.2

起動できない

Erya の画面が出る前の問題です。

表示対処
command not found: eryaPATH にありません。まずフルパスで試し、動くなら PATH の問題です（1.2.3）。
Permission deniedchmod +x erya。
macOS が開発元を検証できない隔離属性：xattr -d com.apple.quarantine erya（1.2.3）。
cannot execute binary fileアーキテクチャ違いです。uname -m で確認（1.2.2）。
対話型ターミナルで実行してくださいパイプやリダイレクトは不可。直接実行します（1.2.8）。
ターミナルが小さすぎます最低 24×6、実用上は 80×24（1.2.8）。
未対応のオプション：…綴り違いか、ハイフン始まりのファイル名。-- を前に置きます（1.2.6）。
… はディレクトリであり…ファイルを渡すか、起動後に Ctrl+O（1.2.5）。
4.3.3

ファイルが開けない

あるいは、思っていたのと違う形で開く場合です。

症状原因と対処
「開けませんでした：Permission denied」読み取り権限がありません。ls -l で確認し、必要なら sudo。
中身が空で開くファイルが存在しません。Erya は未知のパスを新規ファイルとして扱い、最初の保存で作ります（1.2.5）。パスの打ち間違いを確認してください。
16 進数表示で開くNUL バイトを含むためバイナリ扱い（3.3.5）、または非 UTF-8 の大きなファイルです（3.2.1）。
「detected unsupported text encoding: UTF-16LE」UTF-16・UTF-32 は非対応です。先に UTF-8 へ変換してください（3.1.1）。
ステータス行が「大容量ファイル・読み取り専用」64 MiB 以上で、読めますが編集できません（3.2）。
「報告.txt はすでにタブで開いています」エラーではありません。二重に開かず既存のタブへ切り替えました（2.1.1）。
先頭の数行しか見えないスクロールしてください。大きなファイルは必要になってから読みます（3.2.3）。
4.3.4

保存できない

失敗の代償がいちばん大きい場面なので、Erya は厳しめです。

症状原因と対処
「保存に失敗しました：Permission denied」ファイルまたはディレクトリに書き込み権限がありません。アトミック保存はそこに一時ファイルを作ります（2.1.6）。
「保存に失敗しました：No such file or directory」パス途中のディレクトリがありません。Erya は作りません（2.1.9）。
「文書をディレクトリとして保存できません」保存先にディレクトリを指定しています。ファイル名を足してください（2.1.5）。
「大容量ファイルは読み取り専用モードのため編集できません」このモードに保存はありません（3.2.2）。
「このバイナリファイルは読み取り専用のため変更できません」64 MiB 以上のバイナリはストリーム読みの読み取り専用です（3.3.8）。
赤い行が外部変更について尋ねる他のプログラムがファイルを変更しました。迷ったら N、次に F12 で控えを（2.1.7）。
「Big5 に切り替えられません：…」その文字コードで表現できない文字があり、壊すより拒否する設計です（3.1.3）。
4.3.5

キーが効かない

可能性は 4 つ。ありがちな順に。

  1. その操作に既定のキーがない。定型文、マクロ、矩形の埋め・移動、段落の再整形、「カーソル位置の表示」は既定プロファイルで未割り当てです（2.4.8、2.2.6）。F1 でキー欄が空欄かどうか見てください。
  2. 編集画面にいない。画面ごとに使えるキーが違います。2 行目を確認してください（1.3.3）。
  3. そのモードで禁止されている。大容量ファイル読み取り専用は編集系を止め（3.2.2）、テキストファイルの 16 進数表示は読み取り専用です（3.3.1）。メッセージ行に理由が出ます。
  4. ターミナルが送っていない。Alt 組み合わせと修飾付き矢印でよく起きます（4.1.1）。押せるキーに割り当て直してください（4.1.4）。
ターミナルが実際に何を送っているか調べる

試したいキーを、効果が見える操作に割り当てます。cursor_position はカーソル位置をメッセージ行に出します。押して反応があれば、そのターミナルはその組み合わせを送れています。

4.3.6

画面の表示がおかしい

たいていは Erya ではなくターミナル側の問題です。

症状原因と対処
日本語がそろわない／カーソルがずれる等幅でないフォント、または全角の扱いが一致していません。CJK 等幅フォント（Sarasa、Noto Sans Mono CJK など）にしてください。
罫線が変な記号になるターミナルかフォントが対応していません。フォントを変えるか、対応の良いターミナルを使ってください。
色が見づらいErya はターミナルの 16 色を使い、実際の色合いはテーマ次第です。テーマを調整してください。
黄色い 1 行だけになるウィンドウが 24×6 未満です。広げれば戻ります（1.2.8）。
描画のゴミが残るSSH が不安定、または再描画の問題です。ウィンドウサイズを変えると全体を描き直します。
長い行が切れているCtrl+L で折り返すか、End で横スクロールします（2.2.9）。
終了後にターミナルが変になる通常は Erya が状態を復元します。異常時は reset を実行してください。
4.3.7

文字化けする

まず「文字コード違い」か「フォントに字が無い」かを切り分けます。

全体が読めない

文字コードの判定が外れています。F7 で正しく読めるものを探し、保存してください（3.1.2）。ステータス行の後ろから 2 番目に現在の想定が出ています。

一部が □ や ? になる

ターミナルのフォントに字が無いだけです。ファイル自体は無事で、フォントを変えれば出ます。絵文字や珍しい漢字でよく起きます。

化けているあいだは保存しないでください

文字コード違いによる化けは、保存するとファイルに固定されます。F7 で正しい文字コードを見つけ、本文を確かめてから保存してください。分からなければ保存せずタブを閉じます。ディスク上のファイルは無事です。

4.3.8

機能が丸ごと見当たらない

メニューが無いので、「見つからない」はたいてい「未割り当て」か「ここでは非対応」です。

探しているもの実際のところ
すべて選択ありません。Ctrl+Home のあと Ctrl+Shift+End を（2.2.4）。
確認しながら置換そのモードはありません。F3 と F5 で代用します（2.3.4）。
選択範囲内だけ置換対応していません（2.3.7）。
正規表現検索対応していません。完全一致です（2.3.1）。
画面分割ありません。2 ファイルを見比べるには比較機能を（3.4）。
自動保存・クラッシュ復元どちらもありません。Ctrl+S だけです（1.1.7）。
定型文・マクロ・矩形の塗りつぶし機能はありますが既定のキーがありません（2.4.8）。
システムのクリップボード連携Erya のクリップボードは内部用です。ターミナルのコピー＆ペーストを（2.2.7）。
Git 連携、プラグインありませんし、対象範囲にも入っていません（1.1.2）。
4.3.9

それでも解決しないとき

報告に次の情報を添えると、解決がぐっと早くなります。

  1. バージョン：erya --version の出力。
  2. 環境：OS とバージョン、uname -m のアーキテクチャ、使っているターミナル。
  3. キープロファイル：F2 に出ている名前、または自分の keymap.toml。
  4. メッセージ行の文言：一字一句そのまま。いちばん有力な手がかりです。
  5. 再現手順：erya ファイル名 から、押したキーを順に。
  6. ファイルの特徴：サイズ、文字コード、改行コード。すべてステータス行に出ています。
まず既定プロファイルで試してください

報告の前に ERYA_KEYMAP= erya で起動するか、F2 で Erya Terminal Safe に戻して再現するか確かめてください。消えるならキーバインドの問題で、範囲が一気に狭まります。
