1.3.1

The four framing rows

Two rows on top, two at the bottom, everything else is your document.

Whichever screen you are on — editing, opening, comparing, hex, settings — the layout is the same: four framing rows around a content area. Learn to read them and you never get lost.

Two on top, two at the bottom, deliberately

The top two answer “where am I and what can I press”; the bottom two answer “what state am I in and what just happened”. When you are stuck, check row 2 for the key you want, then the last row to see whether Erya said something to you.

1.3.2

Row 1: tabs and titles

Tabs while editing, a screen name everywhere else.

爾雅 Erya │ [report.txt*] appendix.md nginx.conf
(editing: three tabs open, the first one active and not yet saved)
  • The active tab is in square brackets: [report.txt].
  • An asterisk means unsaved changes: [report.txt*]. It disappears when you save.
  • Tabs show the filename only, without the path; a new document shows [Untitled].
  • When there are too many tabs, a ‹ on the left means more are hidden. The active tab is always visible.

On other screens this row becomes the screen name, sometimes with extra context:

If row 1 is not tabs, you are not editing

That is the fastest way to work out where you are. Esc usually takes you back (see 1.3.7).

1.3.3

Row 2: the hint bar

It lists the keys you can press right now, and it follows your key profile.

While editing it always shows the same seven actions:

F1 Help Ctrl+S Save Ctrl+W Search Ctrl+R Replace Ctrl+B Block Ctrl+K Cut line Ctrl+X Exit
This row shows your keys, not the manual's

Apart from F1, which never changes, all of them come from the current key profile. Switch to the nano profile and this row becomes nano's keys. So: when the manual and the screen disagree, the screen is right (see 4.1).

On other screens the row is replaced with that screen's instructions. This is why Erya can do without menus:

1.3.4

The document area and the ~ marks

The large middle block, and those dim blue tildes.

Chapter 1 Background The project began in March 2026. The goal is to convert the existing document set to plain text. ~ ~ ~
  • A dim blue ~ means “the document ends here” — it is not a blank line. A real blank line is simply empty.
  • The content area is the window height minus four. A taller window shows more.
  • The cursor is drawn by the terminal itself; its shape (block, underline, or bar) comes from your terminal settings.
  • Selections are black on grey; search hits and comparison differences are black on yellow.
  • Syntax highlighting is applied from the filename (see 3.1.5); the grey of a selection sits on top of it without interfering.
Full-width characters take two columns

Erya measures in terminal columns: CJK characters, full-width punctuation, and most emoji take two columns; ASCII takes one; tabs expand to the tab width. That is why mixed CJK and Latin text lines up correctly, and why the “column” in the status bar counts characters rather than bytes (see 2.2.3).

1.3.6

The last row: messages and colours

The colour is the severity: yellow reports, white waits for input, red waits for a decision.

Saved report.txt
Search: target string
Unsaved document: S save and exit / Y discard / N return
ColourMeansExamples
YellowA report of what just happenedSaved, Undid last action, No match found, Selection cancelled
WhiteWaiting for you to typeSearch:, Save as:, Go to line/column:
RedWaiting for a decision; nothing continues until you answerUnsaved document, Unsaved tab, File changed externally
When it is red, read it before you press anything

There are exactly three red confirmations: unsaved changes on exit (S/Y/N), unsaved changes on closing a tab (S/Y/N), and an externally changed file on save (O/R/N). Each spells out what every letter does on the same row, and pressing the wrong one really can lose text — in particular Y always means “discard” (see 2.1.8).

The message row is not cleared by your next keystroke; it stays until something replaces it. So when you read a message, check that it refers to what you just did.

1.3.7

Six modes, one Esc

Six full-screen views besides editing, all left the same way.

Two more states affect only the last row: single-line input (search, replace, go to line, save as…) and confirmations (the red ones). Esc cancels both.

Esc always means “one level back”

It cancels a selection while editing, abandons an input, and leaves any full-screen view. When you have no idea where you are and do not want to break anything, Esc is always safe. The one exception is the hexadecimal view of a binary file — there is no text editing to return to, so Esc merely repeats the way out (see 3.3.5).

1.3.8

F1 keyboard help

Erya has no menus, so this list is the feature index.

F1 Open or close keyboard help Up / Down / Left / Right Move the cursor Shift+Up/Down/Left/Right Extend or reverse the selection PageUp / PageDown Move one page up or down Home / End Move to the start or end of the current line Ctrl+Home / Ctrl+End Move to the start or end of the document Ctrl+N Create a blank tab Ctrl+O Open a file in a new tab

F1 is the fixed Help key and cannot be changed by a custom keymap
  • Keys on the left, descriptions on the right; scroll with ↑↓, PageUpPageDown, HomeEnd.
  • The status bar shows which entries you are looking at, out of how many.
  • The first ten are the fixed keys (arrows, Enter, Backspace, Tab, Esc…); the rest are configurable actions.
  • The list shows the keys you actually have. Change profile and it changes with you.
  • Actions with no default key (phrases, macros, block shifting…) show a blank key column: the feature exists, but no key calls it yet (see 2.4.8).
F1 is always F1

Every other action can be rebound; this one cannot. It is a deliberate escape hatch: however unrecognisable your profile becomes, one key still lists everything.

1.3.9

How this manual writes shortcuts

A small convention, so you do not press keys that do nothing.

  1. Ctrl+S in this manual always means “the save key in the Erya Terminal Safe profile”. That is the built-in default, and what you have if you have not changed anything.
  2. If you have switched profiles, work from the action name instead. Every feature has a fixed action name in the program (saving is save), and the tables in 4.4 list both. Those names are also what you write in a config file (see 4.1.5).
  3. The screen is the final authority. Row 2 and F1 show your current keys; when they disagree with the manual, believe them.
Why the defaults avoid the obvious combinations

Because terminals do not deliver every combination. macOS reserves Ctrl+function keys, Alt combinations are often used for special characters, and modified arrows (Ctrl+← and friends) simply never arrive in many terminals. The default profile avoids all of these, so it works in the widest range of terminals, at the cost of leaving a few advanced actions unbound. The original full set survives as Erya Classic and is one keystroke away (see 4.1.1).
