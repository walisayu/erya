# 爾雅 Erya

このディレクトリが Git リポジトリのルートで、`Cargo.toml`、`src/`、`tests/`、`docs/`、`locales/`、`keymap/` を含みます。ローカルの作業ディレクトリでは `Source/` という名前ですが、クローン先の名前は任意です。以下のビルド、テスト、Git、リリースコマンドはこのディレクトリで実行し、追加の `cd Source` は不要です。

製品サイトは同階層の `../Website/` にあり、この Git リポジトリには含まれません。公開サイト：[erya.walisayu.com](https://erya.walisayu.com/)。

[English](README.md) | [繁體中文](README.zh-TW.md) | **日本語**

爾雅 Erya —「爾は近、雅は正」。DOS版『漢書』文書システムをRustで蘇らせるプロジェクトです。仕様駆動・ドキュメント先行の手法で、30年前の中国語文書環境を再構築します。

爾雅は独立開発による実装で、Rustを使って一から書かれています。元の『漢書』のソースコードや資産は一切含まず、元の開発チームとも関係ありません。Linux、macOS、Windowsに対応します。

## Erya 1.0のダウンロード

[GitHub Releases](https://github.com/walisayu/erya/releases/latest)から環境に合うアーカイブをダウンロードしてください。

| システム | アーキテクチャ | Release target |
|---|---|---|
| Linux | Intel／AMD 64-bit | `x86_64-unknown-linux-gnu` |
| Linux／Raspberry Pi OS 64-bit | ARM64 | `aarch64-unknown-linux-gnu` |
| Raspberry Pi OS 32-bit | ARMv7 hard-float | `armv7-unknown-linux-gnueabihf` |
| macOS | Intel | `x86_64-apple-darwin` |
| macOS | Apple Silicon | `aarch64-apple-darwin` |
| Windows | Intel／AMD 64-bit | `x86_64-pc-windows-msvc` |
| Windows | ARM64 | `aarch64-pc-windows-msvc` |

`.tar.gz`を展開し、`erya`（Windowsでは`erya.exe`）を`PATH`に置いてください。同名の`.sha256`またはReleaseの`SHA256SUMS`でダウンロード内容を検証できます。

## 実行

Rust 1.85以降が必要です。

```bash
cargo run --release -- [ファイル]
```

`erya`コマンドをCargoのバイナリーディレクトリにインストールする場合：

```bash
cargo install --path .
erya [ファイル]
```

ファイルを指定しなければ無題の文書を開きます。存在しないパスを指定した場合は、最初の保存時にファイルを作成します。

## リリースパッケージの作成

正式なビルド環境ではDockerを使用しません。[Build environment](docs/BUILD_ENVIRONMENT.md)に記載された固定バージョンのRust、Zig、cargo-zigbuild、cargo-xwinをインストールしてから実行します。

```bash
./build-release.sh
```

フォーマット、Clippy、全テスト、Rust 1.85のMSRVチェック、Cargo package検証の後、7種類のtargetをビルドします。アーカイブ、個別チェックサム、`SHA256SUMS`は`dist/`に生成されます。

1種類だけビルドする場合は`publish.sh`を使用します。Linux／Raspberry Piではglibc互換バージョンと正式なアーカイブ名を別々に指定できます。

```bash
./publish.sh aarch64-apple-darwin
ERYA_BUILD_TOOL=zigbuild \
  ERYA_BUILD_TARGET=aarch64-unknown-linux-gnu.2.17 \
  ./publish.sh aarch64-unknown-linux-gnu
ERYA_BUILD_TOOL=xwin ./publish.sh aarch64-pc-windows-msvc
```

## 表示言語

表示言語は`locales/*.toml`の翻訳ファイルから読み込まれます。繁体字中国語、簡体字中国語、英語、日本語を同梱しています。言語は`ERYA_LANG`、`LC_ALL`、`LC_MESSAGES`、`LANG`の順に判定され、明示的な指定もできます。

```bash
ERYA_LANG=en erya [ファイル]
ERYA_LANG=zh-TW erya [ファイル]
ERYA_LANG=zh-CN erya [ファイル]
ERYA_LANG=ja erya [ファイル]
```

`erya --languages`を実行すると、翻訳ディレクトリで利用できる言語を確認できます。翻訳ファイルを別の場所に置く場合は`ERYA_LOCALES_DIR`を設定してください。翻訳キーがない場合や言語を判定できない場合は、繁体字中国語にフォールバックします。

言語を追加するには、いずれかの`locales/*.toml`をコピーし、言語のメタデータと`[messages]`を編集します。`language.code`は`ERYA_LANG`で使うコード、`language.name`は`--languages`の一覧に表示される名前です。Rustコードの変更は不要です。

```toml
[language]
code = "fr"
name = "Français"

[messages]
new_document = "Nouveau document…"
```

## 対応機能

- UTF-8、UTF-8 BOM、Big5、GBK、Shift_JIS文書のオープン、新規作成、名前を付けて保存。UTF-8以外は自動判定
- タブで複数ファイルを同時編集。タブごとにカーソル、スクロール、検索、元に戻す履歴を保持
- 文字コード、LF／CRLF、ファイル末尾の改行を維持し、必要に応じて変換して保存
- 同じディレクトリの一時ファイルを使ったアトミック保存。Unixでは元ファイルのパーミッションを維持
- 通常の文書にはRopeベースの分割テキストバッファーを使用し、UTF-8保存はチャンク単位でストリーミング出力
- 64 MiB以上のファイルには疎な行インデックスとオンデマンド読み込みによる読み取り専用モードを使用。500 MiBのファイルで検証済み
- ログの追記、切り詰め、ローテーションを自動追跡。カーソルが末尾にある場合は新しい内容を追従
- 通常ファイルの外部変更も検出。未編集なら自動再読込し、ローカル変更がある場合は確認なしの上書きを防止
- 挿入モードと上書きモード
- 改行時に現在行の先頭にある空白とタブのインデントを引き継ぐ
- 矢印キー、Home／End、PageUp／PageDown、横スクロール、`Ctrl+G`による指定行または`行:列`への移動、Shiftによる文字選択、矩形選択
- 結合文字、Emoji、ZWJシーケンスを含むUnicode書記素単位の移動、削除、上書き、表示
- CJK全角文字とTabを考慮した表示幅計算と、切り替え可能なアプリケーション側の折り返し表示
- ファイル名に基づくシンタックスハイライト。選択範囲はハイライト色より優先して表示
- 検索、次を循環検索、1件置換、すべて置換
- TOML、YAML、JSON文書を整形し、TOML／YAMLのコメントを維持
- 最大100段階の元に戻す／やり直し
- 選択範囲または現在行の切り取り、コピー、貼り付け
- エディター内ファイルダイアログ、段落幅設定、段落の再整形
- 左右2ペインのファイル比較、同期スクロール、差分移動、一時作業ファイルを使った安全な双方向ブロックコピー
- ドキュメントを 16 進数ダンプとして表示。左端にオフセット列を置き、1 行 16 または 32 バイト、オフセットは 10／16 進数を切り替え、任意のオフセットへ移動可能
- バイナリファイルは開いた時点でバイト表示になり、バイトの変更、挿入、削除を取り消しと保存つきで行える
- 矩形選択の文字埋めと上下左右移動。座標競合を防ぐため折り返し表示と矩形選択は同時使用不可
- 定型文の登録・循環挿入・JSON入出力と、キーボードマクロの記録・実行・入出力
- 未保存文書を閉じるときの確認
- 翻訳ディレクトリから繁体字中国語、簡体字中国語、英語、日本語を読み込み
- TOMLで一部だけ上書きできるカスタムキーバインド。現在の設定を画面上部に表示
- `F1`でスクロール可能なキーヘルプを表示。カスタムキーバインドも反映
- bracketed pasteへの対応と、終了時のターミナル状態の自動復元

## シンタックスハイライトとLinux設定ファイル

シンタックスは完全なファイル名または拡張子から自動判定されます。Rust、C／C++、Go、Python、Java、JavaScript／TypeScript、Shell、SQL、Markdownなどの一般的なプログラム・文書形式に加え、次のLinux設定ファイルを明示的にサポートします。

- 一般的な`.conf`、`.ini`、`.editorconfig`と、systemdの`.service`、`.socket`、`.timer`、`.mount`、`.target`、`.network`などのunit
- `.env`／`.env.*`、TOML、YAML、JSON、XML
- `.bashrc`、`.profile`、`.zshrc`、`/etc/default/*`
- `.gitconfig`、`sshd_config`、`ssh_config`、`sudoers`、`fstab`、`hosts`、`resolv.conf`
- `nginx.conf`、Apache設定、crontab、Dockerfile／Containerfile、Makefile

1行が64 KiBを超える場合や、カーソルが一度に多くの行を移動した場合は、処理範囲を制限して操作が止まらないようにします。64 MiB以上の大容量ファイルを読み取り専用で開く場合、シンタックスハイライトは無効です。

## 文字コードと改行コードの変換

現在の文字コードと改行コードはステータスバーに表示されます。`F7`でUTF-8、UTF-8 BOM、Big5、GBK、Shift_JISを順に切り替え、`F8`でLF／CRLFを切り替えます。どちらの操作も元に戻す／やり直しができ、次の保存時に変換後の形式で書き込まれます。文書内の文字を変換先の文字コードで表せない場合、その文字コードはスキップされ、代替文字によるデータ破損を防ぎます。

## タブとファイルを開く操作

起動時に複数のパスを指定するか、編集中に`Ctrl+O`を押してファイルダイアログを開きます。ディレクトリは`📂`で表示し、ファイルのアイコン欄は空白にします。矢印キーで選択、`Enter`または`→`でディレクトリへ移動またはファイルを開き、`←`または`Backspace`で親ディレクトリへ戻り、`Esc`または`Q`でキャンセルできます。すでに開いているパスを指定した場合は、そのタブへ切り替えます。各タブは独立した編集状態を保持し、内部クリップボードはタブ間で共有されます。

定型文とマクロは現在文書と同じディレクトリの`.erya-phrases.json`と`.erya-macro.json`に保存します。保存キーを実行したときだけファイルを書き込みます。

`F10`で次のタブ、`F9`で前のタブへ切り替えます。`F11`で現在のタブを閉じます。未保存の変更がある場合は、保存、破棄、キャンセルを確認します。最後のタブを閉じると新しい無題文書が残り、アプリケーション終了時にはバックグラウンドにある未保存タブも順番に確認します。

## 左右2ペインのファイル比較

`F4`を押すと、同じファイルダイアログで左側、右側の順にファイルを選び、比較画面を開きます。追加、削除、変更された行を整列し、変更行の中で異なる書記素をさらに強調表示します。行番号の横には`≠`、`-`、`+`も表示するため、色だけに頼らず差分を確認できます。比較開始時に左右の一時作業ファイルを作成するため、差分をコピーしても元のファイルはすぐには変更されません。

`↑`／`↓`と`PageUp`／`PageDown`で両側共通の`▶`カーソルを移動し、カーソル行全体を同系色の明るい色で強調しながら画面も同期して追従します。長い行は`←`／`→`で同期して横移動します。黄色で示す現在の差分を切り替えるのは`N`／`P`だけで、`Home`／`End`はカーソルを比較の先頭／末尾へ移動します。`Shift+→`はカーソル位置の差分を左から右の一時ファイルへ、`Shift+←`は右から左へコピーします。同一行ではコピーしません。コピー後もカーソルと表示位置を維持し、次の差分へ移動する場合は`N`を押します。

現在のキーマップに設定された保存ショートカットを実行すると、一時的な結果で元のファイルを上書きするか確認します。書き込み前には外部変更も再確認します。未適用の一時変更がある状態で`Esc`を押した場合は、適用、破棄、比較へ戻る、のいずれかを選択できます。

大容量ファイルモードのメモリー上限を維持するため、64 MiB以上の読み取り専用ファイルは左右比較の対象外です。

## 16 進数表示

`Ctrl+P`で現在のドキュメントを 16 進数ダンプとして表示します。この表示は読み取り専用で、BOM、現在のエンコーディング、LF／CRLF の改行を含め、保存時に書き込まれるバイトをそのまま表示します。大きなファイルはメモリに読み込まず、画面に見える範囲だけを読み取ります。

各行の左端はオフセット列で、続いてバイト列と印字可能文字の列を表示します。テキスト編集とバイト表示を往復しても、カーソルは同じバイト上に留まります。

| キー | 機能 |
| --- | --- |
| `Ctrl+P`／`Esc` | テキスト編集に戻る |
| `W` | 1 行 16／32 バイトを切り替え。32 バイトには 144 桁の端末幅が必要で、足りない場合は 16 バイトを維持 |
| `O` | オフセットを 10 進数または 16 進数で表示 |
| `G`／`Ctrl+G` | 指定オフセットへ移動。数字のみは現在のオフセット基数で解釈し、`0x1F`、`$1F`、`1Fh`は常に 16 進数、`0d31`は常に 10 進数 |
| カーソルキー、`PageUp`／`PageDown`、`Home`／`End`、`Ctrl+Home`／`Ctrl+End` | バイト単位、行単位、ページ単位の移動と、行頭行末およびドキュメント先頭末尾への移動 |

### バイナリファイル

テキストとしてデコードできないファイル、または NUL バイトを含むファイルは、開いた時点で 16 進数表示になり、テキスト編集には切り替わりません。操作ヒント行に出口（`F11`でタブを閉じる、`Ctrl+X`で終了）を表示し、`Esc`を押すとステータスバーにも同じ案内が出ます。大容量ファイルのしきい値未満ならバイト列をメモリに保持して編集でき、64 MiB 以上のバイナリファイルは大容量ファイルモードと同じくストリーミングの読み取り専用になります。

編集の単位は文字ではなくバイトです。16 進数を入力すると上位 4 ビット、続いて下位 4 ビットを埋め、2 回の入力で 1 回分の取り消しになります。`I`で上書きと挿入を切り替え（Mac のキーボードには Insert キーがないため。Insert キーがあるキーボードではそちらも使えます）、挿入モードではカーソルを最後のバイトの次に置いて追記できます。`Backspace`はカーソル手前、`Delete`はカーソル位置のバイトを削除し、保存、取り消し、やり直し、名前を付けて保存は通常のキーをそのまま使います。バイナリドキュメントにはテキストバッファがないため、エンコーディング変換、改行変換、左右2ペイン比較は利用できません。

| キー | 機能 |
| --- | --- |
| `0`–`9`、`A`–`F` | 上位 4 ビット、続いて下位 4 ビットを書き込む |
| `I`（または `Insert`） | 上書きと挿入を切り替え。Mac のキーボードには Insert キーがない |
| `Backspace`／`Delete` | カーソル手前、またはカーソル位置のバイトを削除 |
| 保存／取り消し／やり直しのキー | バイト列をファイルに書き戻す、またはバイト編集を1手ずつ戻す |

## キーバインドのカスタマイズ

現在のキーマップの設定ショートカット（既定は`F2`）を押すと、システム設定を開けます。矢印キーでキーマップまたは表示言語を選び、`Enter`ですべてのタブに適用します。キーマップ項目で`E`を押すとKeymap Editorが開きます。操作を選んで`Enter`で編集し、複数のショートカットはカンマで区切ります。完了後に`S`を押すと、完全な設定を新しいTOMLファイルとして保存できます。既存ファイルは上書きしません。

内蔵され、設定画面から直接選択できる`Erya Terminal Safe`プロファイルは、macOSが予約するControl＋ファンクションキー、Option/Meta設定に依存する`Alt`キー、修飾付き矢印キーを避けます。定型文、マクロ、矩形移動など使用頻度の低い操作は初期状態では未割り当てで、Keymap Editorから設定できます。`keymap/`にはErya Classic、nano、vim、emacs、macOS、Eclipse、IntelliJ IDEA Classic、Visual Studio、Visual Studio(macOS)、VSCode、VSCode(macOS)のプロファイルが含まれます。`ERYA_KEYMAPS_DIR`で別のディレクトリを指定できます。`Ctrl+X`と`Ctrl+V`の動作は固定されておらず、常に現在のプロファイルから決まります。

次のコマンドで、すべてのアクション名を含む既定の設定を書き出します。必要な項目だけ残して上書きできます。

```bash
erya --print-default-keymap > keymap.toml
erya --keymap keymap.toml [ファイル]
```

設定値には1つのキー、または複数のキーを指定できます。空の配列を指定すると、そのアクションを無効にできます。キー名では大文字と小文字を区別しません。`Ctrl`、`Alt`、`Shift`、`Super`、`Hyper`、`Meta`、通常の文字、矢印キー、編集キー、`F1`から`F24`までを使用できます。

```toml
[bindings]
save = "Alt+S"
quit = "Ctrl+X"
toggle_rectangular_selection = "Alt+M"
redo = []
```

`ERYA_KEYMAP`で設定ファイルを指定することもできます。指定しない場合は、OSに応じて次のパスを検索します。

- macOS：`~/Library/Application Support/Erya/keymap.toml`
- Linux：`$XDG_CONFIG_HOME/erya/keymap.toml`。XDGが未設定の場合は`~/.config/erya/keymap.toml`
- Windows：`%APPDATA%\Erya\keymap.toml`

設定にないアクションには既定のキーを使用します。設定を解析できない場合やキーバインドの重複を検出した場合は、すべてのキーを既定値に戻し、理由をステータスバーに表示します。

## 大容量ファイルとリアルタイムログ

64 MiB以上のファイルはテキスト全体をバッファーに読み込まず、memory mappingも使用しません。UTF-8の内容をストリーミングで走査し、4096行ごとの疎なチェックポイントだけを保持します。画面に行が必要になった時点で、最も近いチェックポイントから読み込みます。極端に長い1行による過剰なメモリー確保を避けるため、1行のプレビューは先頭1 MiBまでに制限されます。

大容量ファイルモードは読み取り専用で、外部の変更を250ミリ秒ごとに確認します。追記だけの場合は、末尾の未完了行と追加された内容だけを再構築します。ファイルの切り詰め、同一ファイルへの上書き、ログローテーションを検出した場合は、ファイルを開き直してインデックスを再構築します。カーソルがファイル末尾にあれば自動追従し、それ以外の場所に移動した後は現在の閲覧位置を維持します。

| `Ctrl+Y` | やり直し |
| `Shift` + カーソル移動キー | 選択範囲を拡張、または逆方向に縮小 |
| `Ctrl+B` | 矩形選択を開始／解除。開始後はカーソル移動キーで範囲を拡張 |
| `Ctrl+L` | 折り返し表示を切り替え。矩形選択中は有効化不可 |
| `Ctrl+P` | 読み取り専用の 16 進数表示を切り替え |
| `Esc` | 選択を解除 |
| `Ctrl+K` | 現在行を切り取り |
| `Shift+Delete` | 選択範囲を切り取り。未選択時は現在行を切り取り |
| `Ctrl+C` | 選択範囲をコピー。未選択時は現在行をコピー |
| `Shift+Insert` / `Ctrl+V` | 貼り付け。選択中の内容は置換 |
| `Ctrl+D` | 現在行を削除 |
| `Ctrl+A` / `Ctrl+E` | 行頭／行末へ移動 |
| `Insert` | 挿入／上書きを切り替え（Mac のキーボードには Insert キーがないため、キーバインドエディタで割り当てるか Erya Classic の`Alt+I`を使用） |
| `Ctrl+X` | 終了 |
| `F2` | システム設定を開く |
| `F1` | キーヘルプを開く／閉じる |

高度な操作もすべて利用できます。Keymap Editorでキーを割り当てるか、`Erya Classic`を選択すると従来の既定キーをすべて復元できます。
